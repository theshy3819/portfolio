# 사이트형 포트폴리오 기획 (초안 v0.1 · 2026-11-25)

기존 A4 가로 쪽 포트폴리오와 별개로, 스크롤하는 웹사이트형 포트폴리오를 새로 만든다.
아직 만들지 않는다. 이 문서에서 방향을 정한 뒤 단계별로 진행한다.

## 0. 이미 정해진 것

- 기존 쪽 포트폴리오는 PDF로 둔다: `npm run pdf` → `disign/impec/pdf/송호영_포트폴리오.pdf` (A4 가로 18쪽, 저장소에는 올리지 않음)
- 새 사이트는 로컬에서 먼저 만들고 확인한다. 배포 주소는 나중에 정한다.
- 진행 방식: GitHub FE 스킬 선정 → 참고 사이트 REA 분석 → Blender 3D 에셋 → 제작. 적극적이고 창의적으로.
- 내용 규칙은 그대로: `src/content.js`의 확인된 사실만, 팀원 이름 없음, 주만추 저장소 링크 없음, 증명사진(`profile.jpg`) 없음.

## 1. 이 사이트가 증명할 것

- 보는 사람: 채용 담당자 · FE 면접관. 지원서 링크로 데스크톱에서 1~3분, 휴대폰으로도 연다.
- PDF는 "무엇을 만들었나"를 보여 준다. 사이트는 "어떻게 만드는 사람인가"를 보여 준다. 3D · 모션 · 성능 · 접근성을 사이트 자체에서 직접 구현해 증거로 삼는다.
- 이야기 축: UX/UI 디자이너 → 개발자. 캐치프레이즈 "사용성을 설계하며 성장하는 개발자입니다"(유지할지 결정 필요).
- 성공 기준
  - 5초 안에 이름 · 직무 · 대표 작업이 보인다.
  - 30초 안에 프로젝트 4개(WebO · COSMOS · Lumi · 주만추)를 훑는다.
  - 관심 있는 프로젝트 상세로 바로 들어갈 수 있다.
  - 3D가 안 켜져도 내용은 전부 읽힌다.

빼는 것: gsap-core · timeline · utils · performance(기본 지식과 기존 모션 스킬로 충분), gsap-frameworks · tresjs(Vue용), threejs 나머지 항목(R3F 스킬과 겹침), r3f-best-practices · three-best-practices(R3F 스킬의 성능 항목과 겹침, 버전도 한 단계 예전), anthropics frontend-design(impeccable · hallmark와 겹침)

## 4. 기술 스택 — **B로 결정 (2026-11-25)**

React + TypeScript + R3F + drei + GSAP. 3D 비중이 커서 도구·자료가 가장 많은 쪽을 골랐고, COSMOS에서 쓴 스택과 이어진다. `content.js`는 일반 JS라 그대로 가져다 쓴다.

| 안 | 구성 | 장점 | 단점 |
|---|---|---|---|
| A | Vue 3 + TresJS + GSAP | 지금 코드와 content.js를 그대로 재사용. 본인 주력 Vue | 3D 생태계·자료가 R3F보다 적음 |
| B | React + TypeScript + R3F + drei + GSAP | COSMOS에서 쓴 스택. 3D 생태계·스킬·자료가 가장 많음 | 기존 Vue 컴포넌트는 옮겨 써야 함 |
| C | Vite + three.js 직접 + GSAP | 가장 가볍고 세밀하게 제어 | 화면 구성 코드가 길어짐 |

- 공통 후보: Lenis(부드러운 스크롤), Vite, View Transitions(목록 → 상세 전환)
- 3D 에셋 흐름: Blender → GLB → gltf-transform(meshopt 압축, WebP 텍스처) → 사이트에서 지연 로딩

- **관찰**
  - Astro + View Transitions(ClientRouter), three.js r185, Lenis, GSAP. 첫 로드는 약 1.5MB이고, 프로젝트 영상(mp4)은 나중에 받는다.

- **가져올 것**

#### agrumeafarm.it — 3D 퀄리티

- **관찰**
  - Nuxt(Vue) + Vite + three.js r160 + Lenis + GSAP. 내용은 Prismic CMS(`/slice-simulator` 라우트).
  - 홈은 한 화면짜리 병 회전 캐러셀이다. 크림색 바탕, 큰 자주색 도형, 그 위를 도는 원형 문구, 주황 포인트.
  - **병은 GLB 모델이 아니다.** 병 모듈 코드에 `LatheGeometry`(옆모습 선을 돌려 만든 회전체) + `MeshStandardMaterial`(metalness · roughness) + `TextureLoader`만 있다. 병마다 라벨 텍스처 WebP 2장(10~58KB)을 씌운다. 이미지 합계 약 1.2MB, 3D 모델 파일은 0개다.
  - 병마다 작은 캔버스(299×481)와 WebGLRenderer를 따로 만든다(화면에 10개).
  - 쿠키 동의 전에는 스크롤이 막혀 있다.
- **가져올 것**
  1. 고퀄리티의 핵심은 무거운 모델이 아니라 단순한 형태 + 좋은 텍스처 + 금속 · 거칠기 재질 + 조명이다
  2. 천천히 도는 오브젝트 여러 개를 깊이(크기 · 흐림)로 배치하는 구성
  3. 크림 바탕 + 큰 색 면 하나 + 원형 문구처럼 색 면이 화면을 크게 차지하는 대담함
- **피할 것**
  1. 오브젝트마다 WebGL 캔버스를 따로 만드는 구조: 브라우저 컨텍스트 수 제한(보통 16개)에 걸린다. R3F에서는 캔버스 하나에 drei `<View>`로 나눈다
  2. 동의 전 스크롤 잠금
  3. (우리에겐) 한 화면짜리 홈: 우리는 스크롤로 이야기를 전해야 한다

### 우리 기획에 바로 반영할 것

- **스킬 3D 오브젝트는 코드로 만든다.** 프로젝트가 이미 쓰는 `simple-icons`의 SVG 로고를 두께와 모서리 깎임이 있는 입체(ExtrudeGeometry)로 뽑고, 금속 · 유리 재질 + 환경 조명을 준다. GLB가 필요 없어 가볍고 스킬 수만큼 쉽게 늘어난다. Blender는 첫 화면의 대표 오브젝트처럼 코드로 못 만드는 것에만 쓴다.
- **3D는 캔버스 하나:** 고정된 R3F `<Canvas>` 하나 + drei `<View>`로 섹션마다 3D 자리를 나눈다.
- **프로젝트 목록:** wheel(기본, 가운데 1장 + 양옆 바퀴) · grid · list 세 가지 배열. 배열을 바꿀 때 카드가 제자리에서 이동하는 전환(GSAP Flip — 그때 `gsap-plugins` 스킬 추가). 카드 휘는 셰이더는 약하게.
